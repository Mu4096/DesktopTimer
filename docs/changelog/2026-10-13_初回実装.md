## メモ


### ステップ1：状態遷移とカウントダウン表示

- 構成：`src/DesktopTimer`（WPF 本体）＋ `tests/DesktopTimer.Tests`（xUnit。TimerService と時間書式のみ）。ソリューションは .NET 10 の既定形式 `DesktopTimer.slnx`
- `TimerService`：UI 非依存の状態遷移（Idle / Running / TimeUp）。残り時間は開始時刻との差分で計算
  - 時刻源は `ITimeSource` で抽象化。本番は `Environment.TickCount64`（GetTickCount64）。システム時計変更の影響を受けず、スリープ中も進むので復帰後に実時間で再計算できる
  - Running 中の `Start` は無視（false を返す）。TimeUp からの `Start` は新規開始
  - `TimeSinceTimeUp` は TimeUp を検出した時点から数える（ステップ3の音の自動停止用。スリープ復帰で TimeUp になった場合も復帰時点から60秒鳴る）
- `TimerViewModel`：200ms 周期の DispatcherTimer で表示更新（Running 中のみ動かす）
- 表示書式：残り時間は秒未満切り上げ（開始直後が 10:00、00:00 は時間切れの瞬間のみ）、経過時間は切り捨て。60分以上は h:mm:ss
  - 仕様書の TimeUp 表示 `0:00` は、mm:ss 書式に揃えて `00:00` としている
- 点滅：TimeUp 中は XAML のアニメーションで 0.5 秒ごとに表示/非表示を切り替え（1周期1秒）
- TimeUp 中の左クリック（本体部分）で解除。Running 中の左クリックは何もしない
- 仮実装：右クリックメニューは「キャンセル」のみ（ステップ2で揃える）。ウィンドウは通常の枠付き（ステップ2で枠なしに）。プリセットは 10分 / 30分 固定（ステップ4で設定から読む）
- 動作確認用：Debug ビルドで `--short` を付けて起動するとプリセットが 10秒 / 30秒 になる
- csproj：`UseWindowsForms` による暗黙 using（System.Windows.Forms / System.Drawing）は WPF と型名が衝突するので除外。警告 WFO0003（WinForms 向けの「manifest で DPI 設定するな」）は WPF には当てはまらないので NoWarn

### ステップ2：ウィンドウ（枠なし・最前面・グリップ移動・右クリックメニュー）

- `WindowStyle=None` / `AllowsTransparency=True` / `ShowInTaskbar=False` / `Topmost=True`。外枠は角丸（6DIP）の Border で描画
- ウィンドウサイズは 240×110 DIP 固定で、中身は Viewbox で比例拡大（ステップ7でウィンドウサイズをスケールに連動させる）
- 初期位置：`MonitorHelper.MoveToPrimaryBottomRight`。Win32 の物理ピクセル座標で、プライマリモニター作業領域の右下から 16DIP（配置先モニターの DPI で換算）内側に置く
  - DPI の異なるモニターから移す場合に移動後のサイズが変わるため、移動 → 実サイズ取得 → 置き直し の2段階で配置
  - 表示前に置くため `OnSourceInitialized` で実行。ウィンドウは Left=0/Top=0（必ずプライマリ上）で生成している
- 移動：グリップの MouseLeftButtonDown で `DragMove()`。本体部分は移動しない。グリップ上の ⚙ ボタンはクリックを自分で処理するのでドラッグにならない
- 右クリックメニュー：キャンセル / 設定...（ステップ4まで無効）/ 位置をリセット / 終了
- 未実装（後続ステップ）：移動完了時の位置保存（ステップ4、`Grip_MouseLeftButtonDown` に TODO）、⚙ ボタンと「設定...」（ステップ4。現在は無効表示）
- 注意：タスクバーにもトレイにも出ないので、ステップ8まではアプリの終了は右クリック →「終了」のみ

### ステップ3：音声再生（デフォルト音源・ループ・自動停止）

- NAudio は 3.1.0 が入った。3.x では `WaveOutEvent` が `WaveOut`（イベントコールバック方式）に改名されているので `WaveOut` を使う（旧名は CS0618 警告になる）
- `SoundCatalog`：`C:\Windows\Media\Alarm01〜10.wav` のうち存在するもの＋内蔵ビープを一覧化。ID は `system:Alarm01.wav` / `builtin:beep` 形式（ユーザー音源はステップ6で `user:` を追加予定）
  - `Resolve`：ID が見つからない・ファイルが無い場合は内蔵ビープで代替
- `SoundService`：`AudioFileReader`（wav/mp3）または埋め込み WAV → `LoopStream`（末尾で先頭に戻す）→ `VolumeSampleProvider` → `WaveOut`。音量 0 なら再生しない。開けないファイルは内蔵ビープで代替、出力デバイスが無い等の再生エラーは握りつぶして続行
- `AlarmController`：TimeUp に入ったら再生、抜けたら停止。自動停止は 500ms 周期で `TimerService.TimeSinceTimeUp` を見て判定（スリープをまたいでも実時間で止まる）。音だけ止め、表示は TimeUp のまま
- 内蔵ビープ `Assets/beep.wav`：1kHz・0.1秒のピッ×3回（間0.1秒）＋0.5秒無音＝約1秒、22.05kHz/16bit/モノラル、前後5msフェード。PowerShell で生成し EmbeddedResource（`DesktopTimer.Assets.beep.wav`）として埋め込み
- 確認：一時テストで Alarm01・内蔵ビープ・存在しない ID（→ビープ）がいずれもファイル長を超えてループ再生されること、音量0で鳴らないことを確認済み（テスト自体は削除）
- 仮実装：音源 Alarm01・音量 80%・自動停止 60秒 は固定（ステップ4で設定から読む）。Debug ビルドの `--short` では自動停止を 5秒 にする
- トースト通知はトレイ（ステップ8）で実装

### ステップ4：設定の保存/読込と設定画面

- `AppSettings`（Models）：10.1 の全項目＋ウィンドウ位置。INotifyPropertyChanged で変更を通知し、各所が購読して即時反映する
  - 範囲は定数（`PresetMinutesMin` 等）で定義。`Normalize()` で読み込み後に範囲外を補正、null をデフォルトで補完
  - `ResetToDefaults()` は設定項目を戻すがウィンドウ位置は維持（位置は「位置をリセット」で戻せるため）
  - ホットキーは `HotkeySetting(ModifierKeys, Key)`、位置は `WindowPosition(X, Y)`（物理ピクセル）。JSON では enum を文字列で保存
- `SettingsService`：`%APPDATA%\DesktopTimer\settings.json`。壊れていれば `settings.json.bak` に退避してデフォルトで起動。読めないだけ（ロック等）なら退避しない
  - 保存は一時ファイル → 置き換え。変更から 500ms 後にまとめて保存（スライダー操作で連続書き込みしない）、終了時に `Flush()`
- 設定画面：機能が実装済みの項目のみ表示（プリセット1/2、タイムアップ音＋試聴、音量、自動停止、すべてデフォルトに戻す）。他の項目の UI は各機能のステップで追加する
  - 数値は TextBox ＋ `IntRangeRule`。範囲外・非数値は赤枠＋ツールチップで、設定には反映しない
  - 音源一覧は ListBox。選択中に ✔、各行に試聴/停止ボタン（ステップ6の追加・削除もこの一覧に足す）。試聴はタイムアップ音とは別の SoundService で鳴らし、音量スライダーは試聴中の音にも即反映。画面を閉じると停止
  - 「すべてデフォルトに戻す」は確認ダイアログを出す（仕様に記載なし。誤操作防止のため追加）
- ウィンドウ位置：グリップのドラッグ完了時に保存、起動時に復元。保存位置のウィンドウがどのモニターの作業領域にも収まらなければデフォルト位置（判定は左上の点があるモニターで行う）。「位置をリセット」で保存位置を null に戻す
  - モニター識別情報の保存、DisplaySettingsChanged、DPI の異なるモニターへの復元はステップ9
- Debug の `--short`：プリセット値を「秒」として扱う（設定の 10/30 がそのまま 10秒/30秒 になる）。ステップ3の自動停止 5秒 上書きは廃止（設定画面で 5秒 にできるため）
- 注意：Slider の Minimum/Maximum は double なので `x:Static` で int 定数を渡すと実行時に例外になる（リテラルで指定している）

### ステップ5：グローバルホットキー

- `HotkeyService`：メッセージ専用ウィンドウ（HwndSource、親 HWND_MESSAGE）で `RegisterHotKey` / `WM_HOTKEY` を扱う。タイマーウィンドウの表示状態に依存しない。`MOD_NOREPEAT` 付きで登録（押しっぱなしで連続発火しない）
  - 設定のホットキーが変わったら3つとも登録し直す。状態は `HotkeyStatus`（Registered / NotAssigned / Conflict / Duplicate）
  - アプリ内で同じキーが重なった場合は後の操作を Duplicate として登録しない（仕様に記載なし。警告文を競合と分けるため追加）
- 操作の実行：ホットキー → TimerViewModel のコマンドを実行。Running 中のプリセット開始はコマンドの CanExecute が false なので無視される。キャンセルは Running / TimeUp の両方で Idle に戻す
- 設定画面：3行の入力欄（読み取り専用 TextBox で PreviewKeyDown を拾う）。登録失敗時は赤字の警告
  - 入力欄にフォーカスがある間は `Suspend()` でホットキーを一時解除（割り当て済みのキーを押すとタイマーが動いてしまうため）。解除中の設定変更は「登録して即解除」で競合の有無だけ確認する
  - 受け付けるのは Ctrl / Alt / Win を含む組み合わせか F1〜F24 単体（Shift＋文字などで普段の入力を奪わないため）。Delete / Backspace で割り当てなし（`HotkeySetting.None`、表示「なし」）。修飾キーなしの Tab はフォーカス移動
- 確認：キー送信で Ctrl+Alt+1 開始 → Running 中の Ctrl+Alt+2 無視 → Ctrl+Alt+0 キャンセルを確認。別プロセスで Ctrl+Alt+2 を先に登録した状態で設定画面に競合警告が出ることを確認。入力欄で割り当て済みのキーを押してもタイマーが動かないこと、重複警告、Delete での解除を確認
- 改善（ユーザー指摘：受付中か分かりにくい）：入力欄を選ぶと「キーを押してください…（Esc で取り消し）」を水色背景・青太字で表示。キーを登録したら受付を終える（フォーカスを外す）。Esc で取り消し
  - フォーカスを外す時は論理フォーカスも外す（`Keyboard.ClearFocus()` だけだと、ウィンドウを切り替えて戻った時に入力欄へフォーカスが戻り受付が再開する）

### ステップ6：ユーザー音源の追加・削除

- `UserSoundLibrary`：`%APPDATA%\DesktopTimer\sounds\` にコピーして管理。ID は `user:<ファイル名>`、表示名はファイル名（拡張子込み。同名の wav/mp3 を区別するため）。同名があれば「名前 (2).mp3」のように番号を付ける。対応形式は .wav / .mp3（大文字小文字は区別しない）
  - 一覧は sounds フォルダを毎回列挙する（設定ファイルには一覧を持たない）
- `SoundCatalog.GetAllSources`：標準アラーム → 内蔵ビープ → 追加音源 の順。タイムアップ時（AlarmController）も追加音源を含めて解決する
- `SoundService.CanOpen`：追加前に NAudio で開けるか確認し、開けなければエラー表示して追加しない（拡張子だけ合っている壊れたファイル対策）
- 設定画面：「追加...」（OpenFileDialog）、追加音源の行にだけ「削除」ボタン。仕様に記載のない判断として以下を追加
  - 追加した音源は自動で選択し、一覧をその行までスクロール
  - 削除は確認ダイアログを出す。試聴中なら止めてから削除。選択中の音源を削除したらデフォルト（Alarm01）を選択し直す（一覧から消す前に移す。消した後だと ListBox の選択解除で SoundId が null になるため）
  - 再生中などで削除に失敗したらエラー表示
  - 設定画面を開いた時に選択中の音源までスクロール（Loaded 直後は選択・行生成が未完了なので ContextIdle で実行）
- 確認：mp3 は Media Foundation の MP3 エンコーダで生成したもので、CanOpen・ループ再生・壊れた mp3 の拒否を確認。設定画面で追加（コピー・選択・スクロール）→ 壊れた mp3 のエラー表示 → 削除（ファイル削除・Alarm01 に戻る）を自動操作で確認

### ステップ7：サイズ変更・不透明度・色変化

- サイズ：ウィンドウの Width/Height ＝ 基準 240×110 DIP × ScalePercent。中身は Viewbox で比例拡大。左上の位置を固定して伸縮する
  - 右下ハンドル（Thumb）は Viewbox の外に重ね、スケールに関係なく同じ大きさ。ウィンドウにマウスが乗っている間とドラッグ中だけ表示
  - ドラッグ中はウィンドウ左上からのマウス座標で目標サイズを求め、幅・高さそれぞれの倍率の大きい方を採用（縦横比固定）。差分の積み上げにしないのはスケールの整数丸めでずれるため
  - 設定画面の「サイズ」スライダーと同じ ScalePercent を共有
  - 起動時は位置の復元前にサイズを反映（画面内判定にサイズを使うため）
- 不透明度：Window.Opacity ＝ OpacityPercent / 100（AllowsTransparency なのでウィンドウ全体が半透明になる）
- 色変化：`TimerViewModel.IsWarning` ＝ Running 中で残り時間 ≤ 警告閾値（閾値 0 なら無効）、または TimeUp 中。残り時間の文字色と進捗バーを警告色（#F0643C）に。TimeUp の点滅も警告色
  - 文字色は DataTrigger で切り替えるため、直接指定ではなくスタイルの Setter で既定色を設定している（直接指定するとトリガーより優先される）
  - Debug の `--short` では警告閾値も「秒」扱い（10秒タイマーで残り1秒から警告色）
- 設定画面に「表示」セクション（サイズ・不透明度スライダー、警告色の分数）を追加
- 確認：警告色（通常 → 残り1秒で警告色 → TimeUp）、ハンドルのホバー表示とドラッグでの拡大（縦横比維持・左上固定）、スライダーでの 200% / 50% / 不透明度 40% をスクリーンショットで確認
- 補足：画面端の近くで拡大すると、ウィンドウが画面外にはみ出すことがある（左上固定のため。仕様に記載がないので現状のまま）

### ステップ8：タスクトレイ・自動起動・多重起動防止

- アイコン `Assets/app.ico`：青い角丸四角にストップウォッチ。PowerShell＋System.Drawing で生成。16/20/24/32/40/48/64 は 32bit BMP、256 は PNG で格納（System.Drawing.Icon は小サイズの PNG 格納を読めないため）。exe のアイコン（ApplicationIcon）と埋め込みリソース（トレイ用）を兼ねる
- `TrayIconService`：WinForms の NotifyIcon。メニューは 表示/非表示（文言は状態で切替）・キャンセル（Running/TimeUp のみ有効）・設定...・位置をリセット・終了。ダブルクリックで表示/非表示。終了時に Visible=false にしてから破棄（残像防止）
- 通知：TimeUp 時、設定 ON なら `ShowBalloonTip`（Windows 10/11 ではトースト）。「時間です / 10分のタイマーが終了しました。」。通知クリックでタイマーを表示
  - トレイから非表示にしている間に TimeUp しても、ウィンドウは勝手に出さない（音と通知は出す）。仕様に記載なし
- `AutoStartService`：HKCU\...\Run の値 `DesktopTimer` に `"<exe パス>"`。起動時と設定変更時に反映（exe を移動しても次回起動で追従）。`dotnet DesktopTimer.dll` 起動時は隣の DesktopTimer.exe を登録
  - 注意：デフォルト ON なので、このビルドを起動した時点で（Debug ビルドなら Debug の exe が）登録される
- 多重起動防止：名前付き Mutex `Local\DesktopTimer.SingleInstance`。2つ目は名前付きイベント `Local\DesktopTimer.ShowExisting` をセットして終了し、1つ目は ThreadPool で待ち受けてタイマーを表示する
- 設定画面：「タイムアップ時に通知を表示する」「Windows の起動時に自動で起動する」のチェックを追加
- 確認：起動で Run に登録、設定のチェックで解除/登録、トレイアイコン表示とメニュー項目、トレイから非表示 → 2つ目の起動で再表示（2つ目は終了コード 0 ですぐ終了）を自動操作で確認。確認後に Run の値は確認前の状態（未登録）に戻した。トースト通知の表示は手動確認

### ステップ9：マルチモニタ・DPI・全画面検出

- 構成：Win32 呼び出しは `MonitorHelper`（モニター列挙・ウィンドウ矩形・移動）、計算は `PlacementCalculator`（純粋関数、テストあり）に分離。全画面の判定も `FullscreenWatcher.IsFullscreen`（純粋関数、テストあり）に分離
- 位置の保存（8.3）：`WindowPosition(X, Y, MonitorDeviceName, MonitorLeft, MonitorTop)`。識別情報はデバイス名（`\.\DISPLAY2` など）と保存時のモニター左上。ステップ8までの座標だけの形式もそのまま読める
  - 復元：同じデバイス名のモニターがあれば、そのモニター上の同じ相対位置へ（ディスプレイ設定で並べ替えても追従。仕様に記載のない拡張）。無ければ座標のまま。いずれもウィンドウ全体が作業領域に収まらなければデフォルト位置
  - 収まるかの判定・デフォルト位置の計算は、置き先モニターのスケールでウィンドウサイズ・余白を換算
  - `SystemEvents.DisplaySettingsChanged`：UI スレッドで、今の矩形がどのモニターの作業領域にも収まらなければデフォルト位置へ。静的イベントなのでウィンドウを閉じる時に解除
- DPI：Per-Monitor V2 の DPI 変更は WPF が処理する。`MonitorHelper.MoveTo` は移動後に位置がずれていたら置き直す（DPI の異なるモニターへの移動でサイズが変わる時のため）
- 全画面検出（8.2）：1秒周期。フォアグラウンドウィンドウがタイマーと同じモニターの全域を覆えば全画面。除外：Progman / WorkerW / シェルウィンドウ / 自分のプロセス / タイトルバー付きで最大化されたウィンドウ（タスクバー自動非表示だと通常の最大化でも全域を覆うため。仕様に記載のない除外）
- 表示制御：App で「ユーザーの表示希望（トレイの表示/非表示）」と「全画面中か」を分けて持ち、両方から表示を決める。トレイメニューの文言はユーザーの希望に従う。全画面中の TimeUp は強制表示しない（音・通知は通常どおり）
  - 再表示でフォーカスを奪わないよう TimerWindow は `ShowActivated="False"`
- 設定画面「表示」に「全画面のアプリの表示中はタイマーを隠す」チェックを追加
