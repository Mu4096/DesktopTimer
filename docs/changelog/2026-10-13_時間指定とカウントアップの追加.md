# 時間指定とカウントアップの追加

- 日付：2026-10-13
- 種別：機能追加
- 関連する仕様書の章：3, 4.2, 4.5, 4.6, 4.7, 4.9（新設）, 5, 7, 9, 10.3, 12, 13

## 背景・目的

普段はプリセットをすぐ開始する使い方だが、好きな時間を指定して開始したいこともある。また、カウントアップ（ストップウォッチ）としても使いたい（v1 では対象外にしていた）。待機画面にボタンを増やすとうるさくなるため、どちらも右クリックメニューから使う。

実装前にユーザーに確認して決めたこと：

- メニューは2項目に分ける。「時間を指定して開始...」は入力用の小窓を開き、「カウントアップ開始」は入力なしですぐ始める
- 入力画面はタイマーの近くに出す小さな別ウィンドウ（時・分・秒の3欄＋開始ボタン、Enter で開始・Esc で閉じる、前回の時間を記憶）
- カウントアップを止めたら、結果を表示したまま止める。左クリックで待機画面へ戻る（TimeUp の解除と同じ操作）
- カウントアップ中の進捗バーは「1分ごとに満ちるバー」

## 変更内容

- 状態と時間計算（`Models/TimerState.cs`, `Services/TimerService.cs`）
  - 状態に `Stopped`（止めたカウントアップの結果を表示中）を追加。計り方 `TimerMode`（CountDown / CountUp）を追加
  - `StartCountUp()`：Running 以外から開始。経過時間は開始時刻との差分で計算し、終わりは無い（TimeUp にならない）
  - `Stop()`：カウントアップの Running → Stopped。止めた時点の経過時間を保持する。カウントダウン中は何もしない
  - `Cancel()` は Stopped からも Idle に戻す。`Start()` は Stopped からも新規開始できる
- 表示（`ViewModels/TimerViewModel.cs`, `Views/TimerWindow.xaml`）
  - `RemainingText` / `ElapsedText` / `IsCountdownVisible` を `TimeText` / `SubText` / `IsTimeDisplayVisible` に改名（カウントアップでは大きい数字が経過時間になるため）
  - カウントアップ中は「カウントアップ中」、Stopped では「■ 停止中 ・ クリックで閉じる」（ティール）。警告色にはしない
  - 進捗バー：カウントアップでは `MinuteProgress`（今の1分の経過割合）を表示。カウントダウンは従来どおり残り割合
  - `CancelCommand` はカウントアップの計測中だけ「停止」として働く（`CancelLabel` で文言も「停止」に）。キャンセルのホットキー・トレイメニューも同じコマンドを使うので同様に動く
  - `DismissCommand`（左クリック）は TimeUp に加えて Stopped でも有効
  - 右クリックメニューに「時間を指定して開始...」「カウントアップ開始」を追加（Running 中は無効）。キャンセル項目は計測中だけ「停止」＋停止アイコン
- 時間指定の小窓（新規：`Views/CustomTimerWindow.xaml(.cs)`, `ViewModels/CustomTimerViewModel.cs`, `Services/DurationInput.cs`）
  - 時・分・秒の3欄。入力の解釈（空欄は0、全角数字可、範囲 0〜23 / 0〜59 / 0〜59、合計0は不可、↑↓・ホイールの増減）は `DurationInput` の純粋関数に分けてテストを書いた
  - 入力の誤りは `INotifyDataErrorInfo` で通知し、既存の TextBox スタイルのピンクの枠で示す
  - 位置は `PlacementCalculator.GetPopupPosition`（純粋関数、テストあり）：タイマーの上に右端をそろえ、入らなければ下、どちらも無理なら作業領域内。大きさは固定（340×208 DIP）にして、表示前に置き先モニターのスケールで換算して配置する（SizeToContent だと配置時点で大きさが決まっていないため）
  - 開始ボタン用に `PrimaryButtonStyle`（ティールの塗り）を `Themes/Controls.xaml` に追加
  - `App.ShowCustomTimer`：小窓は1つだけ。開いていれば前面に出す
- 設定（`Models/AppSettings.cs`）：`LastCustomSeconds`（前回指定した時間、初期値5分、1秒〜23:59:59 に補正）。古い settings.json（項目なし）はデフォルト値で読める
- 通知の文言：`TimeFormat.DurationLabel` を追加し「1時間30分のタイマーが終了しました。」のように表す（従来の `PresetLabel` では 90分 / 90秒 になるため）
- トレイメニュー：キャンセル項目の文言を開くたびに `CancelLabel` から更新
- README の基本操作、仕様書（3章の状態遷移、4.5 メニュー、4.9 新設 ほか）を更新。12章（対象外）からカウントアップを削除

### 仕様に記載のない判断

- 時間指定の上限は 23:59:59（プリセットの上限180分より長くしたが、日をまたぐ指定は想定しない）
- 前回の時間の記憶は設定画面には出さず、「すべてデフォルトに戻す」でも戻さない（ウィンドウ位置と同じく操作の記憶のため）
- 小窓は開いたまま他の操作もできる（モーダルにしない）。開いている間にホットキーでタイマーが動き出したら開始ボタンを無効にし、理由を表示する
- 入力欄では IME を無効にする（数字をそのまま打てるように）
- 時間指定・カウントアップの開始にホットキーは設けない。トレイメニューにも開始項目は足していない

## 確認

- `dotnet build --no-incremental`：警告・エラー 0。`dotnet test`：110 件すべて合格（追加 42 件：TimerService のカウントアップ・Stopped、DurationInput、GetPopupPosition、DurationLabel、LastCustomSeconds の保存・補正）
- ユーザーのタイマーが起動していなかったため、Debug ビルドを `--short` 付きで起動し、UI Automation とマウス・キー送信で確認（操作前に確認用インスタンスのプロセス ID のウィンドウであることを確かめた）
  - 右クリックメニューの項目と、Running 中に開始項目が無効・キャンセルが「停止」になること
  - 小窓：タイマーの上に右端をそろえて開く、「分」の欄にフォーカス、合計0で案内と開始ボタン無効、範囲外の値でピンクの枠、ホイールでの増減、Enter で開始して閉じる、Esc で閉じる、前回の時間（8秒）が次に開いた時に入っている、開いたままホットキーでプリセットが始まると開始できない旨を表示
  - 指定した 8 秒でカウントダウン → TimeUp → クリックで解除
  - カウントアップ：経過時間が増える・Running 中の左クリックで何も起きない・メニューの「停止」で結果を表示したまま止まる・左クリックで待機画面へ
  - ホットキー：カウントアップ中のプリセットは無視、`Ctrl+Alt+0` で停止 → もう一度で待機画面、Stopped からプリセットのホットキーで新規開始
  - 初版の小窓はツールウィンドウ（幅300）にしていたが、「秒」が切れることと、閉じるボタンが常に赤く表示されることを撮影で確認したため、設定画面と同じ通常のタイトルバー・幅340に変更した
- 確認後、settings.json はバックアップから戻し、Run キーも確認前の値（普段使いの exe）に戻した
- ユーザーに確認を依頼した項目（トレイメニューの「停止」表示、小窓の位置と使い心地、カウントアップの見た目、通知の文言）は、通知以外すべて OK
- 未確認：DPI の異なるモニターでの小窓の位置（手元の2台はどちらも 100%）

### 通知が表示されない件（このアプリの不具合ではない）

ユーザーの確認で「タイムアップ時に通知が表示されない」との報告があった。調査の結果、原因はこのアプリではなく Windows 側の判定だった。

- `SHQueryUserNotificationState` が `QUNS_BUSY`（全画面アプリの使用中）を返していた。この状態では、トレイアイコンのバルーン通知を Windows が表示しない
- 原因はデスクトップマスコット「DesktopMate」の透明なウィンドウで、プライマリモニター全体（画面より大きい矩形）を覆っているため全画面アプリと判定されていた
- ユーザーが確認：DesktopMate を終了すると通知が表示される。DesktopMate とタイマーを別のモニターに置いて表示領域が重ならないようにした場合も表示される
- ユーザーの判断で、アプリ側の修正はしない
