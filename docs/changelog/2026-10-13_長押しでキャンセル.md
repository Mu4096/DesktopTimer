# 長押しでキャンセル・停止

- 日付：2026-10-13
- 種別：機能追加
- 関連する仕様書の章：3, 4.6, 13

## 背景・目的

タイマー動作中のキャンセルと、カウントアップの停止を、右クリックメニューに加えて左クリックの長押しでもできるようにしたい（ユーザーの要望）。誤操作防止のため Running 中の普通のクリックは引き続き何もしない。

実装前にユーザーに確認して決めたこと：

- 長押しの時間は1秒
- 押している間は真ん中に丸いゲージを出し、一周したら実行する

## 変更内容

- 円形ゲージ（新規：`Views/ProgressArc.cs`）
  - `Progress`（0〜1）の割合だけ、真上から時計回りに弧を描く `Shape`
- 本体（`Views/TimerWindow.xaml`）
  - 本体の Grid に `BodyGrid` と名前を付け、長押し用のマウスイベントを追加
  - 長押し中のオーバーレイ `HoldOverlay`：本体をほぼ不透明な下地で暗くし、中央に下地の輪（`Ellipse`）・伸びる弧（`ProgressArc`、56 DIP・太さ7・両端は直線）・アイコンを重ねる。カウントダウンのキャンセルはピンクに ✕、カウントアップの停止はティールに ■（右クリックメニューのアイコンと同じ）
- 長押しの処理（`Views/TimerWindow.xaml.cs`）
  - Running 中の左ボタン押下でマウスをキャプチャする。0.3秒たったらオーバーレイをフェードイン（0.08秒）し、ゲージを0.7秒で一周させる（どちらも `DoubleAnimation` の `BeginTime` で遅らせる）。一周したら `CancelCommand`（カウントアップの計測中は停止）を実行する
  - `PreviewMouseLeftButtonDown` で受ける。本体の `MouseBinding`（TimeUp 解除・Stopped を閉じる `DismissCommand`）より先に確実に受け取るため。Running 以外では何もせず従来どおり処理させる
  - 中断：一周する前に離す、ポインターが本体の外へ出る、キャプチャを失う（右クリックメニューが開いた等）、`State` が変わる（残り0で TimeUp、キャンセルキー等）。中断したアニメーションの完了は通し番号で無視する
- 仕様書（3章の表、4.6、13章）と README の基本操作を更新

### ユーザーの確認を受けての見直し

1. 初版（円形・太さ5・弧の両端が丸い・押した瞬間から1秒で一周）に対して、「もっと太く、他の UI に合わせて角張ったデザインに」「短いクリックでも毎回ゲージが出る」との指摘
   - 進捗バーの目盛りに合わせた四角いマス目のゲージを試作し、少し押し続けてからゲージが現れるようにした
2. 表示のタイミングは好評。見た目は「マス目ではなく最初の円形に近い形で、両端を直線に、少し太く」との指摘
   - 円形に戻し、弧の両端を直線（`Flat`）に、太さを5→7（大きさ52→56 DIP）にした。マス目のゲージ（`SegmentGauge`）とそのテストは削除した
   - 仕様書 4.8 の「丸い部品も角の丸い四角にする」の例外として 4.6 に明記した

### 仕様に記載のない判断

- 長押しの合計は1秒のまま（ユーザーが選んだ時間）とし、ゲージが現れるまで0.3秒・一周するまで0.7秒に分けた
- ゲージを出している間は本体を暗くする（大きい時間表示の上にゲージを重ねても見えるように）。初版より下地を濃くし、後ろの数字が透けにくいようにした
- ポインターが本体の外へ出たら中断する（押したまま離れる＝やめたい、と扱う）
- 実行した後にボタンを離しても何も起きない。止めたカウントアップ（Stopped）はクリックで閉じるが、閉じるのは次のクリックから。カウントダウンをキャンセルした後に現れるプリセットボタンも、離しただけでは押されない
- 長押しの時間は設定項目にしない（固定）

## 確認

- `dotnet build --no-incremental`：警告・エラー 0。`dotnet test`：110 件すべて合格（追加のテストなし。変更は UI の操作と描画のみ）
- ユーザーの普段使いのタイマーが起動中だったため、確認用インスタンスは起動していない。代わりに scratchpad のハーネス（App を new せず、テーマのリソース辞書だけ読み込んで `TimerWindow` を表示）で確認した
  - 見た目：ゲージ 35% / 100%（カウントダウン、ピンク ✕）、60%（カウントアップ、ティール ■）を画像にして、弧の両端が直線で切れていることを確認
  - 実際のマウス入力（`SetCursorPos` / `mouse_event`）で次の8項目を確認：0.2秒の短いクリックではゲージが表示されず Running のまま／長押しで0.6秒時点にゲージが表示され（進捗約0.4）、一周するとキャンセルし、離しても Idle のまま／カウントアップを長押しで停止し、離しても Stopped のまま／Stopped はクリックで閉じる／押したまま外へ出ると中断／途中で離すと中断し、再度の長押しでキャンセル／長押し中に TimeUp になると中断して TimeUp のまま／TimeUp はクリックで解除
    - 最終版で3回流し、2回目・3回目は全項目が期待どおり。1回目は2項目目の長押しが途中で中断された（ゲージが消えて Running のまま。3・4項目目はその連鎖で失敗）。確認中に実際のマウスが動いて本体の外へ出た（仕様どおりの中断）可能性が高いが、断定はできていない
  - ハーネス実行後、Run キー（普段使いの exe）と settings.json（更新時刻がハーネス実行前）に変化がないことを確認
- ユーザーに確認してもらった内容：長押しの動作（表示までの間・一周の速さ）と、最終版のゲージの見た目（太さ・両端が直線）・スケール変更時の見え方は OK
