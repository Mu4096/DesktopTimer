# アラーム機能の追加

- 日付：2026-10-14
- 種別：機能追加
- 関連する仕様書の章：3, 4.2, 4.5, 4.6, 4.10（新設）, 5, 7, 10.3, 13

## 背景・目的

指定した時刻に鳴るアラームが欲しい（ユーザーの要望）。時間指定のタイマー・カウントアップと並べて右クリックメニューから使う。

実装前にユーザーに確認して決めたこと：

- アラームはタイマー本体を使う（指定時刻までのカウントダウンとして動き、待っている間はほかのタイマーを開始できない）。裏で別に待つ方式にはしない
- 待っている間の本体は残り時間を大きく表示し、下に「7:30 にアラーム」を出す
- 時刻の入力は時・分の2欄（24時間制）。過ぎた時刻なら翌日のその時刻に鳴らす
- 繰り返しはなし（1回だけ）

## 変更内容

- 状態と時間計算（`Services/TimerService.cs`）
  - `Start(duration, alarmTime)` に鳴らす時刻（省略可）を追加し、`AlarmTime` で持つ。計り方は通常のカウントダウン（`TimerMode.CountDown`）のままで、状態遷移・TimeUp・音は既存の処理をそのまま使う
  - `AlarmTime` はキャンセル・解除・別の開始（カウントダウン・カウントアップ）で null に戻す
- 時刻の計算（新規：`Services/AlarmInput.cs`）。純粋関数に分けてテストを書いた
  - `TryCompose`：時・分の2欄から時刻を組み立てる（欄の読み方は `DurationInput.TryParseField` と共通。0:00 も可）
  - `GetDelay`：現在時刻から次にその時刻になるまでの時間。今日の時刻を過ぎていれば（同じ時刻も含む）翌日
  - `DescribeSchedule`：「今日の 15:00 に鳴ります（あと 36分）」の案内。残りは分単位に切り上げる
  - `GetInitialTime`：初回の初期値（次の正時）
  - `TimeFormat.ClockLabel`：時刻の表記（7:30、23:05）
- 表示（`ViewModels/TimerViewModel.cs`, `Views/TimerWindow.xaml(.cs)`）
  - 右クリックメニューの時間指定の項目と「カウントアップ開始」の間に「アラーム（時間指定）...」（ベルのアイコン、Running 中は無効）。時間指定の項目は「時間を指定して開始...」から「タイマー（時間指定）...」に改名（下記「ユーザーの確認を受けての見直し」）
  - アラームの待機中は補足の文字を「7:30 にアラーム」にし、前にベルのアイコン（`IsAlarm`）を添える
  - `StartAlarm(delay, alarmTime)` を追加（Running 中は何もしない）
- アラームの小窓（新規：`Views/AlarmWindow.xaml(.cs)`, `ViewModels/AlarmViewModel.cs`）
  - 時・分の2欄＋鳴る時刻の案内＋「セット」ボタン。案内は開いている間1秒ごとに更新する
  - 小窓を開いている間にタイマーが動き出したら「タイマーの動作中は開始できません」を表示してセット不可（時間指定の小窓と同じ）
  - `App.ShowAlarm`：小窓は1つだけ。開いていれば前面に出す
- 時間指定の小窓との共通化（リファクタリング）
  - 入力欄のスタイル（`TimeFieldBoxStyle` / `TimeFieldUnitStyle`）を `CustomTimerWindow.xaml` から `Themes/Controls.xaml` へ移した
  - 入力欄の操作（全選択、↑↓キー・ホイールでの増減）をコードビハインドから添付ビヘイビア `Views/TimeFieldBehavior.cs` に移した。増減は DataContext の `ITimeFieldStepper`（新規。`CustomTimerViewModel` と `AlarmViewModel` が実装）に任せる
  - 小窓の配置・タイトルバーの配色・Esc で閉じる処理を基底クラス `Views/AnchoredDialogWindow.cs` にまとめ、`CustomTimerWindow` と `AlarmWindow` で使う
- 通知（`App.xaml.cs`）：アラームでは「時間です / 7:30 のアラームです。」
- 設定（`Models/AppSettings.cs`）：`LastAlarmMinutes`（前回指定した時刻。0:00 からの分、未指定は null、0〜1439 に補正）。古い settings.json（項目なし）は null として読める。「すべてデフォルトに戻す」でも戻さない
- 仕様書（3, 4.2, 4.5, 4.6, 4.10 新設, 5, 7, 10.3, 13章）と README の基本操作を更新

### ユーザーの確認を受けての見直し

- 初版のメニューの文言「時間を指定して開始...」「時刻を指定してアラーム...」は、どちらも「〜を指定して」で始まるため見分けにくいとの指摘を受け、それぞれ「タイマー（時間指定）...」「アラーム（時間指定）...」に変更した（`Views/TimerWindow.xaml`、仕様書 3, 4.5, 4.9, 4.10, 13章、README）
  - 小窓を開く項目に付けている「...」は「設定...」と同じ慣例なので残した
  - 小窓のタイトル（「時間を指定して開始」「時刻を指定してアラーム」）は変えていない

### 仕様に記載のない判断

- 待つ時間はセットした瞬間の現在時刻（`DateTime.Now`）から求め、以降は他のカウントダウンと同じ単調増加時刻との差分で計る。スリープをまたいでも実時間で進むが、待っている間にシステム時計を大きく変えた場合は追従しない（NTP の補正程度のずれは無視できる）
- 初回の初期値は「開いた時刻の次の正時」（例：14:23 に開けば 15:00）。2回目からは前回セットした時刻
- 小窓には「↑↓ キー・ホイールで増減」に加えて、鳴る時刻の案内（今日 / 明日、あと何分）を常に出す。過ぎた時刻が翌日になることが入力中に分かるように
- 開始ボタンの文言は「セット」、アイコンはベル（Segoe Fluent Icons の EA8F）。メニュー・本体の補足も同じベルにした
- 小窓の大きさは時間指定と同じ幅340、高さは案内が1行多い分 208→226
- アラームの残りが警告閾値以下になったら、他のカウントダウンと同じく警告色にする
- アラームの開始にホットキーは設けない。トレイメニューにも追加していない

## 確認

- `dotnet build --no-incremental`：警告・エラー 0。`dotnet test`：142 件すべて合格（追加 32 件：AlarmInput、TimerService のアラーム時刻、ClockLabel、LastAlarmMinutes の保存・補正・維持）
- ユーザーのタイマーが起動していなかったため、Debug ビルドを `--short` 付きで起動し、UI Automation とマウス・キー送信で確認（操作前に確認用インスタンスのプロセス ID のウィンドウであることを確かめた）
  - 右クリックメニューにアラームの項目が並び、Running 中は開始系の3項目が無効になる
  - 小窓：タイマーの上に開く、初期値が次の正時（11:07 に開いて 12:00、「あと 53分」）、過ぎた時刻で「明日の 11:00 に鳴ります（あと 23時間53分）」、範囲外（75分）でピンクの枠とセット不可
  - 11:08:32 に 11:10 でセット → 小窓が閉じ、本体に「01:28」とベル・「11:10 にアラーム」→ 11:10:00 ちょうどに TimeUp（「♪ クリックで止める」）→ クリックで待機画面へ
  - 次に開くと前回の 11:10 が入っている（settings.json の `LastAlarmMinutes` は 670）。↑キーで時が増え、全選択のまま
  - 時間指定の小窓（共通化した入力欄）も↑キーで増減・全選択・Esc で閉じることを確認
  - アラームの小窓を開いたままホットキーでプリセットを始めると「タイマーの動作中は開始できません」でセット不可。通常のカウントダウンには「経過 00:01 / 00:30」と表示され、ベルは出ない
- 確認後、settings.json はバックアップから戻し、Run キーも確認前の値（普段使いの exe）に戻した
- 未確認：アラームのトースト通知の文言（普段の設定で通知が OFF のため表示されなかった）、アラーム待機中の長押しキャンセル（他のカウントダウンと同じ処理）
